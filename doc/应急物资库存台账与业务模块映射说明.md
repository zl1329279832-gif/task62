# 应急物资库存台账与业务模块映射说明

> **文档用途**：应急局验收时对照物资台账与各业务模块的关系，说明当前代码"做了什么、没做什么"。
> **生成日期**：2026-06-13
> **对应代码版本**：springbootxnj6l（基于 Spring Boot 2.2.2 + MyBatis-Plus 2.3）

---

## 一、台账核心概念速览

| 台账要素 | 对应数据库表 / 字段 | 说明 |
|----------|---------------------|------|
| **物资主档（品类台账）** | `wuzixinxi` 表 | 每种物资一行，`wuzishuliang` 字段存储当前库存数量 |
| **入库流水** | `wuziruku` 表 | 每次入库一条记录，含入库编号、物资名称、数量、日期 |
| **出库流水** | `wuzichuku` 表 | 每次出库一条记录，含出库编号、物资名称、数量、日期、出库类型、领用人 |
| **申领流水** | `wuzishenling` 表 | 每次申领一条记录，含申领单号、申领数量、审核状态（`sfsh`） |
| **库存数量字段** | `wuzixinxi.wuzishuliang`（Integer） | 由入库、审批通过自动增减，是唯一被代码维护的"实时库存"字段 |

### 关键中间服务：`KucunService`（库存服务）

代码中有一个 **`KucunServiceImpl`**（`com.service.impl.KucunServiceImpl`），它不在 Controller 直接暴露，而是被 `WuzirukuController`、`WuzishenlingController`、`WuzixinxiController` 注入调用。它是台账数字一致性的核心保障层，负责：

- `increaseStock()` — FOR UPDATE 悲观锁 + 增加 `wuzixinxi.wuzishuliang`
- `createRequisition()` — 创建申领单，快照当前库存，自动设置 `sfsh="待审核"`
- `approveRequisition()` — FOR UPDATE 悲观锁 + 扣减库存 + 自动生成出库记录 + 设置 `sfsh="已出库"`
- `rejectRequisition()` — 设置 `sfsh="拒绝"`，不动库存
- `lowStockAlert()` — 按物资分类聚合低库存预警

## 二、逐模块对照说明

### 2.1 物资入库模块 — `WuzirukuController`（`/wuziruku`）

| 端点 | 方法签名 | 台账影响 |
|------|----------|----------|
| `POST /save` | `save(@RequestBody WuzirukuEntity)` | **写入库流水 + 联动增加库存**。调用 `wuzirukuService.insert()` 后调用 `kucunService.increaseStock(wuzimingcheng, wuzishuliang)`，使用 `@Transactional` 保证原子性 |
| `POST /add` | `add(@RequestBody WuzirukuEntity)` | 与 `/save` 相同逻辑，前端入口 |
| `PUT /update` | `update(@RequestBody WuzirukuEntity)` | **仅更新入库记录本身**，不回滚或重算库存（`@Transactional` 但无 KucunService 调用） |
| `DELETE /delete` | `delete(@RequestBody Long[] ids)` | **仅删除入库记录**，不回滚已增加的库存 |
| `GET /page` | `page(params, WuzirukuEntity)` | 分页查询入库流水，不影响台账 |
| `GET /list` | `list(params, WuzirukuEntity)` | 前端列表（`@IgnoreAuth` 无需登录） |
| `GET /lists` | `list(WuzirukuEntity)` | 全量列表 |
| `GET /query` | `query(WuzirukuEntity)` | 条件查询 |
| `GET /info/{id}` | `info(Long id)` | 单条详情 |
| `GET /detail/{id}` | `detail(Long id)` | 前端详情（`@IgnoreAuth`） |
| `GET /remind/{col}/{type}` | `remindCount(...)` | 提醒计数，按列值和时间范围筛选 |
| `GET /value/{xCol}/{yCol}` | `value(...)` | 按值统计（SUM 聚合） |
| `GET /value/{xCol}/{yCol}/{timeType}` | `valueDay(...)` | 按时间维度统计（日/月/年） |
| `GET /group/{col}` | `group(...)` | 分组统计（COUNT） |

**实际做了什么：**
- 入库保存时自动增加 `wuzixinxi.wuzishuliang`
- 使用 FOR UPDATE 悲观锁，防止与审批并发时库存数字不一致
- `@Transactional` 保证入库记录和库存更新在同一事务中

**没做什么（缺口）：**
- **修改入库记录不会重算库存**：改了 `wuziruku.wuzishuliang`，`wuzixinxi.wuzishuliang` 不会联动调整
- **删除入库记录不会回滚库存**：已增加的库存不会因入库记录被删而扣回
- **无入库单号自动生成**：`rukubianhao` 需要前端传入，后端不生成
- **无物资存在性校验**：如果 `wuzimingcheng` 在 `wuzixinxi` 表中不存在，`increaseStock()` 会抛异常但无友好提示

### 2.2 物资出库模块 — `WuzichukuController`（`/wuzichuku`）

| 端点 | 方法签名 | 台账影响 |
|------|----------|----------|
| `POST /save` | `save(@RequestBody WuzichukuEntity)` | **仅写入出库流水，不扣减库存**。无 `@Transactional`，无 KucunService 调用 |
| `POST /add` | `add(@RequestBody WuzichukuEntity)` | 与 `/save` 相同，**不扣减库存** |
| `PUT /update` | `update(@RequestBody WuzichukuEntity)` | 仅更新出库记录（`@Transactional`） |
| `DELETE /delete` | `delete(@RequestBody Long[] ids)` | 仅删除出库记录 |
| `GET /page` | `page(params, WuzichukuEntity)` | 分页查询；**如果是 yonghu 角色登录，自动过滤只看自己的出库记录** |
| `GET /list` | `list(params, WuzichukuEntity)` | 前端列表（`@IgnoreAuth`），不做用户过滤 |
| `GET /value/{xCol}/{yCol}` | `value(...)` | 按值统计；yonghu 角色自动加 `yonghuming` 过滤 |
| `GET /value/{xCol}/{yCol}/{timeType}` | `valueDay(...)` | 按时间统计；yonghu 角色自动加 `yonghuming` 过滤 |
| `GET /group/{col}` | `group(...)` | 分组统计；yonghu 角色自动加 `yonghuming` 过滤 |
| `GET /remind/{col}/{type}` | `remindCount(...)` | 提醒计数；yonghu 角色自动加 `yonghuming` 过滤 |

**实际做了什么：**
- 纯 CRUD 出库流水记录
- 普通用户（yonghu）只能看到和操作自己的出库记录

**没做什么（缺口）：**
- **手动出库不扣减库存**：直接通过 `/save` 或 `/add` 创建的出库记录，`wuzixinxi.wuzishuliang` 不会减少。这意味着手动出库与台账库存脱节
- **库存不足不拦截**：没有库存校验，即使库存为 0 也能创建出库记录
- **无出库单号自动生成**：`chukubianhao` 需要前端传入
- **与申领审批流程脱节**：只有通过 `WuzishenlingController.approve` 自动生成的出库记录才会扣减库存，手动出库完全不走库存服务

> **重要说明**：出库记录的库存扣减 **只发生在申领审批通过时**（`KucunServiceImpl.approveRequisition()`），而非通过出库模块自身的 save/add。这是台账闭环的关键设计点，也是验收时容易被误解的地方。

### 2.3 物资申领模块 — `WuzishenlingController`（`/wuzishenling`）

| 端点 | 方法签名 | 台账影响 |
|------|----------|----------|
| `POST /save` | `save(@RequestBody WuzishenlingEntity)` | **创建申领单**：自动设置 `sfsh="待审核"`，快照当前库存到 `wuzishuliang` 字段。通过 `kucunService.createRequisition()` |
| `POST /add` | `add(@RequestBody WuzishenlingEntity)` | 与 `/save` 相同 |
| `POST /approve` | `approve(Map params)` | **审批通过**：FOR UPDATE 锁 + 扣减 `wuzixinxi.wuzishuliang` + 自动生成 `wuzichuku` 出库记录（`chukuleixing="申领出库"`）+ 设置 `sfsh="已出库"` |
| `POST /reject` | `reject(Map params)` | **审批拒绝**：设置 `sfsh="拒绝"` + 审核回复，不扣库存 |
| `PUT /update` | `update(@RequestBody WuzishenlingEntity)` | 仅更新申领记录 |
| `DELETE /delete` | `delete(@RequestBody Long[] ids)` | 仅删除申领记录 |
| `GET /page` | `page(params, WuzishenlingEntity, shenlingriqistart, shenlingriqiend)` | 分页查询，支持申领日期范围过滤；yonghu 角色只看自己的 |
| `GET /list` | `list(params, WuzishenlingEntity, shenlingriqistart, shenlingriqiend)` | 前端列表（`@IgnoreAuth`），支持日期范围 |
| `GET /lists` | `list(WuzishenlingEntity)` | 全量列表 |
| `GET /query` | `query(WuzishenlingEntity)` | 条件查询 |
| `GET /info/{id}` | `info(Long id)` | 单条详情 |
| `GET /detail/{id}` | `detail(Long id)` | 前端详情（`@IgnoreAuth`） |
| `GET /remind/{col}/{type}` | `remindCount(...)` | 提醒计数；yonghu 角色自动加 `yonghuming` 过滤 |

**实际做了什么：**
- 完整的申领-审批流程：创建申领单 -> 管理员审批通过/拒绝
- 审批通过时原子扣减库存 + 自动生成出库记录 + 更新状态为"已出库"
- 审批拒绝时仅改状态，不动库存
- 创建申领单时快照当前库存到 `wuzishuliang` 字段（便于审批时对比）
- 使用 FOR UPDATE 悲观锁保证审批时库存并发安全
- 库存不足时审批会抛异常拒绝操作

**没做什么（缺口）：**
- **无申领统计 API**：`WuzishenlingService` 没有 `selectValue` / `selectTimeStatValue` / `selectGroup` 方法，无法做申领趋势图表
- **申领数量与库存快照字段易混淆**：`wuzishuliang`（快照当前库存）和 `shenlingshuliang`（实际申领数量）字段名不够直观
- **已出库的申领单可以被 update/delete**：没有状态保护，已完成的申领单可以被修改或删除
- **审批接口无权限校验**：任何登录用户都可以调用 `/approve` 和 `/reject`，没有限制为管理员角色
- **申领单号不自动生成**：`shenlingdanhao` 需要前端传入

| `POST /add` | `add(@RequestBody WuzixinxiEntity)` | 与 `/save` 相同 |
| `PUT /update` | `update(@RequestBody WuzixinxiEntity)` | 更新物资信息（`@Transactional`），可能直接修改 `wuzishuliang` |
| `DELETE /delete` | `delete(@RequestBody Long[] ids)` | 删除物资主档（逻辑删除，`logic-delete-value: -1`） |
| `GET /page` | `page(params, WuzixinxiEntity)` | 分页查询物资主档 |
| `GET /list` | `list(params, WuzixinxiEntity)` | 前端列表（`@IgnoreAuth`） |

| `GET /info/{id}` | `info(Long id)` | 单条详情 |
| `GET /detail/{id}` | `detail(Long id)` | 前端详情（`@IgnoreAuth`） |
| `GET /value/{xCol}/{yCol}` | `value(...)` | 按值统计（SUM） |
| `GET /value/{xCol}/{yCol}/{timeType}` | `valueDay(...)` | 按时间统计 |
| `GET /group/{col}` | `group(...)` | 分组统计（COUNT） |
| `GET /remind/{col}/{type}` | `remindCount(...)` | 提醒计数 |
| **`GET /lowStockAlert`** | `lowStockAlert(threshold)` | **低库存预警**：返回 `wuzishuliang <= threshold` 的物资，按 `wuzifenlei` 分组聚合 |

**实际做了什么：**
- 物资主档的 CRUD 管理
- 提供低库存预警查询（`/lowStockAlert?threshold=10`）
- 提供统计图表数据接口

**没做什么（缺口）：**
- **`wuzishuliang` 可被直接修改**：管理员可以通过 `/update` 接口直接改 `wuzishuliang`，绕过入库/出库流程，导致台账与实际流水不一致
- **删除物资不检查关联流水**：删除物资主档时不检查是否有入库/出库/申领记录
- **save 无事务保护**：`/save` 和 `/add` 没有 `@Transactional` 注解
- **无物资编码自动生成**：物资没有编码字段，仅靠 `wuzimingcheng`（物资名称）做关联键

## 五、附录 A：WuzichukuController 现有统计 API 入参/口径

### A.1 按值统计 — `GET /wuzichuku/value/{xColumnName}/{yColumnName}`

| 项目 | 说明 |
|------|------|
| **功能** | 按 `xColumnName` 分组，对 `yColumnName` 做 SUM 聚合 |
| **入参** | `xColumnName`（路径参数）— 分组列名，如 `wuzifenlei`、`chukuriqi` |
| | `yColumnName`（路径参数）— 聚合列名，如 `wuzishuliang` |
| **SQL** | `SELECT ${xColumn}, sum(${yColumn}) total FROM wuzichuku WHERE 1=1 ${ew} GROUP BY ${xColumn}` |
| **权限过滤** | 如果登录用户角色为 `yonghu`，自动追加 `WHERE yonghuming = '当前用户名'` |
| **返回** | `List<Map<String, Object>>`，每项含 `{xColumn值, total}` |
| **日期格式化** | 返回结果中 Date 类型自动格式化为 `yyyy-MM-dd` |
| **典型用例** | `GET /wuzichuku/value/wuzifenlei/wuzishuliang` — 各物资分类的出库数量汇总 |
| | `GET /wuzichuku/value/chukuleixing/wuzishuliang` — 各出库类型的出库数量汇总 |

### A.2 按时间统计 — `GET /wuzichuku/value/{xColumnName}/{yColumnName}/{timeStatType}`

| 项目 | 说明 |
|------|------|
| **功能** | 按时间维度（日/月/年）分组，对 `yColumnName` 做 SUM 聚合 |
| **入参** | `xColumnName`（路径参数）— 时间列名，通常为 `chukuriqi` |
| | `yColumnName`（路径参数）— 聚合列名，如 `wuzishuliang` |
| | `timeStatType`（路径参数）— 时间粒度，可选值：`日`、`月`、`年` |
| **SQL（日）** | `SELECT DATE_FORMAT(chukuriqi,'%Y-%m-%d') chukuriqi, sum(wuzishuliang) total FROM wuzichuku WHERE 1=1 ${ew} GROUP BY DATE_FORMAT(chukuriqi,'%Y-%m-%d')` |
| **SQL（月）** | `SELECT DATE_FORMAT(chukuriqi,'%Y-%m') chukuriqi, sum(wuzishuliang) total FROM wuzichuku WHERE 1=1 ${ew} GROUP BY DATE_FORMAT(chukuriqi,'%Y-%m')` |
| **SQL（年）** | `SELECT DATE_FORMAT(chukuriqi,'%Y') chukuriqi, sum(wuzishuliang) total FROM wuzichuku WHERE 1=1 ${ew} GROUP BY DATE_FORMAT(chukuriqi,'%Y')` |
| **权限过滤** | 同 A.1，yonghu 角色自动过滤 |
| **返回** | `List<Map<String, Object>>`，每项含 `{时间字符串, total}` |
| **典型用例** | `GET /wuzichuku/value/chukuriqi/wuzishuliang/月` — 按月统计出库数量 |

### A.3 分组统计 — `GET /wuzichuku/group/{columnName}`

| 项目 | 说明 |
|------|------|
| **功能** | 按 `columnName` 分组，统计每组的记录数（COUNT） |
| **入参** | `columnName`（路径参数）— 分组列名，如 `wuzifenlei`、`chukuleixing`、`yonghuming` |
| **SQL** | `SELECT ${column}, count(1) total FROM wuzichuku WHERE 1=1 ${ew} GROUP BY ${column}` |
| **权限过滤** | 同 A.1，yonghu 角色自动过滤 |
| **返回** | `List<Map<String, Object>>`，每项含 `{column值, total}` |
| **典型用例** | `GET /wuzichuku/group/chukuleixing` — 各出库类型的记录数 |
| | `GET /wuzichuku/group/wuzifenlei` — 各物资分类的出库记录数 |

### A.4 提醒计数 — `GET /wuzichuku/remind/{columnName}/{type}`

| 项目 | 说明 |
|------|------|
| **功能** | 统计指定列在时间范围内满足条件的记录数 |
| **入参** | `columnName`（路径参数）— 筛选列名 |
| | `type`（路径参数）— 类型，`"2"` 表示日期范围模式 |
| | `remindstart`（查询参数）— 起始偏移天数（相对于今天） |
| | `remindend`（查询参数）— 结束偏移天数（相对于今天） |
| **SQL 逻辑** | `WHERE columnName >= (今天+remindstart天) AND columnName <= (今天+remindend天)` |
| **权限过滤** | 同 A.1，yonghu 角色自动过滤 |
| **返回** | `{ "count": N }` |

### A.5 统计口径重要说明

> **注意**：以上所有统计 API 查询的是 **`wuzichuku` 出库流水表**，统计的是"出库记录中记载的数量"，**不等于台账库存变动**。因为：
> 1. 手动通过 `/wuzichuku/save` 创建的出库记录不扣减库存
> 2. 只有通过申领审批（`/wuzishenling/approve`）自动生成的出库记录才与库存变动一致
> 3. 出库记录的 `chukuleixing` 字段可区分"申领出库"（审批自动生成）和其他类型（手动创建），但统计 API 本身不做区分
