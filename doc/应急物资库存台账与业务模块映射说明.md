# 应急物资库存台账与业务模块映射说明

> 编写日期：2026-06-13
> 适用系统：应急救援物资管理系统（springbootxnj6l）
> 代码分支：claude-documentation

---

## 一、文档目的

本文档面向应急局验收评审，逐模块说明系统四个核心业务控制器（入库、出库、申领、物资信息）在代码层面**实际做了什么**和**没有做什么**，厘清 `wuzixinxi.wuzishuliang`（台账主表库存数量字段）与各业务流程之间的联动关系，并如实列出当前实现的缺口。

---

## 二、核心概念：`wuzishuliang` 在四张表中的不同含义

| 数据表 | 字段 `wuzishuliang` 含义 | 说明 |
|--------|--------------------------|------|
| `wuzixinxi` | **当前库存量**（台账主数据） | 系统中的库存"真值"，被 KucunService 自动维护 |
| `wuziruku` | 本次入库数量 | 单笔入库操作的物资数量 |
| `wuzichuku` | 本次出库数量 | 单笔出库操作的物资数量 |
| `wuzishenling` | 申领时刻的库存快照 | 创建申领单时自动抓取 `wuzixinxi.wuzishuliang` 的快照值，仅供参考 |

> `wuzishenling` 表中还有单独的 `shenlingshuliang`（申领数量）字段，代表用户实际申请领取的数量，与 `wuzishuliang`（快照库存）含义不同。

## 三、逐模块对照

### 3.1 WuzixinxiController — 物资信息（台账主表）

**路由前缀**：`/wuzixinxi`
**注入服务**：`WuzixinxiService`、`KucunService`

#### 已实现的功能

| API 端点 | 功能说明 | 权限 |
|----------|----------|------|
| `GET /page` | 后台分页查询物资信息列表 | 需登录 |
| `GET /list` | 前台分页查询物资信息列表 | @IgnoreAuth，无需登录 |
| `GET /lists` | 全量列表查询（带视图） | 需登录 |
| `GET /query` | 单条查询，返回 `WuzixinxiView` | 需登录 |
| `GET /info/{id}` | 按 ID 查询详情（后台） | 需登录 |
| `GET /detail/{id}` | 按 ID 查询详情（前台） | @IgnoreAuth |
| `POST /save` | 新增物资信息（后台） | 需登录 |
| `POST /add` | 新增物资信息（前台） | 需登录 |
| `POST /update` | 修改物资信息（@Transactional） | 需登录 |
| `POST /delete` | 批量删除 | 需登录 |
| `GET /remind/{columnName}/{type}` | 提醒计数（到期/阈值类） | 需登录 |
| `GET /value/{xColumnName}/{yColumnName}` | 按列聚合统计（SUM） | 需登录 |
| `GET /value/{xColumnName}/{yColumnName}/{timeStatType}` | 按时间粒度聚合统计 | 需登录 |
| `GET /group/{columnName}` | 按列分组计数（COUNT） | 需登录 |
| `GET /lowStockAlert?threshold=N` | 低库存预警（按分类聚合） | 需登录 |

#### 代码实际做了什么

- **CRUD 完整**：支持物资信息的增删改查。
- **统计 API 完整**：支持按任意列 SUM 聚合、按日/月/年时间维度聚合、按列 COUNT 分组。
- **低库存预警**：`/lowStockAlert` 调用 `kucunService.lowStockAlert(threshold)`，执行 SQL：
  ```sql
  SELECT wuzifenlei, COUNT(*) AS lowStockCount,
         GROUP_CONCAT(wuzimingcheng SEPARATOR ',') AS wuziNames,
         MIN(wuzishuliang) AS minQuantity
  FROM wuzixinxi WHERE wuzishuliang <= #{threshold} GROUP BY wuzifenlei
  ```
  返回按物资分类聚合的低库存物资清单。

#### 代码没有做什么

- **`/save` 和 `/add` 是纯插入**：没有事务注解（`/save`、`/add` 均无 `@Transactional`），不校验物资名称是否重复。可以创建同名物资，而 KucunService 按名称匹配库存，可能导致混乱。
- **`/update` 不拦截 `wuzishuliang` 手工修改**：管理员可以直接修改库存数量字段，绕过入库/出库流程，系统不记录修改原因，不生成审计日志。
- **`/delete` 不检查关联出入库记录**：删除物资信息时不检查是否存在关联的入库、出库、申领记录，可能导致历史台账断链。
- **无操作日志**：所有修改没有审计追踪。

### 3.2 WuzirukuController — 物资入库

**路由前缀**：`/wuziruku`
**注入服务**：`WuzirukuService`、`KucunService`

#### 已实现的功能

| API 端点 | 功能说明 | 权限 | 事务 |
|----------|----------|------|------|
| `GET /page` | 后台分页查询入库记录 | 需登录 | — |
| `GET /list` | 前台分页查询入库记录 | @IgnoreAuth | — |
| `GET /lists` | 全量列表 | 需登录 | — |
| `GET /query` | 单条查询 | 需登录 | — |
| `GET /info/{id}` | 按 ID 详情（后台） | 需登录 | — |
| `GET /detail/{id}` | 按 ID 详情（前台） | @IgnoreAuth | — |
| `POST /save` | 新增入库记录 + 自动增加库存 | 需登录 | **@Transactional** |
| `POST /add` | 新增入库记录 + 自动增加库存 | 需登录 | **@Transactional** |
| `POST /update` | 修改入库记录 | 需登录 | @Transactional |
| `POST /delete` | 批量删除入库记录 | 需登录 | — |
| `GET /remind/{columnName}/{type}` | 提醒计数 | 需登录 | — |
| `GET /value/...` | 聚合统计（SUM） | 需登录 | — |
| `GET /value/.../timeStatType` | 时间粒度聚合统计 | 需登录 | — |
| `GET /group/{columnName}` | 分组计数 | 需登录 | — |

#### 代码实际做了什么

- **入库联动库存**：`/save` 和 `/add` 在 `@Transactional` 事务中执行两步操作：
  1. `wuzirukuService.insert(wuziruku)` — 插入入库记录
  2. `kucunService.increaseStock(wuzimingcheng, wuzishuliang)` — 调用库存服务增加库存
- **`increaseStock` 内部逻辑**（`KucunServiceImpl`）：
  1. 校验物资名称非空、数量 > 0
  2. `SELECT * FROM wuzixinxi WHERE wuzimingcheng = ? FOR UPDATE` — **悲观锁**锁行
  3. 读取当前 `wuzishuliang`，加上入库数量
  4. `wuzixinxiService.updateById()` 持久化新库存值
- **入库编号自动生成**：`id` 由 `new Date().getTime() + random` 生成。

#### 代码没有做什么

- **`/update` 不回滚库存差额**：修改入库记录的数量时，不会自动调整 `wuzixinxi.wuzishuliang`。例如把入库数量从 100 改为 50，库存不会减少 50。
- **`/delete` 不回扣库存**：删除入库记录后，之前增加的库存量不会被扣减，导致库存虚高。
- **无用户角色过滤**：所有端点不区分用户身份，任何登录用户均可操作。
- **统计 API 不区分角色**：入库统计报表对所有登录用户可见。

### 3.3 WuzichukuController — 物资出库

**路由前缀**：`/wuzichuku`
**注入服务**：`WuzichukuService`（**未注入 KucunService**）

#### 已实现的功能

| API 端点 | 功能说明 | 权限 | 用户过滤 |
|----------|----------|------|----------|
| `GET /page` | 后台分页查询出库记录 | 需登录 | "yonghu"角色只能看自己的记录 |
| `GET /list` | 前台分页查询 | @IgnoreAuth | 无过滤 |
| `GET /lists` | 全量列表 | 需登录 | 无 |
| `GET /query` | 单条查询 | 需登录 | 无 |
| `GET /info/{id}` | 按 ID 详情 | 需登录 | 无 |
| `GET /detail/{id}` | 按 ID 详情（前台） | @IgnoreAuth | 无 |
| `POST /save` | 新增出库记录 | 需登录 | 无 |
| `POST /add` | 新增出库记录 | 需登录 | 无 |
| `POST /update` | 修改出库记录 | 需登录 | 无 |
| `POST /delete` | 批量删除 | 需登录 | 无 |
| `GET /remind/{columnName}/{type}` | 提醒计数 | 需登录 | "yonghu"角色过滤 |
| `GET /value/...` | 聚合统计（SUM） | 需登录 | "yonghu"角色过滤 |
| `GET /value/.../timeStatType` | 时间粒度聚合统计 | 需登录 | "yonghu"角色过滤 |
| `GET /group/{columnName}` | 分组计数 | 需登录 | "yonghu"角色过滤 |

#### 代码实际做了什么

- **纯 CRUD**：`/save` 和 `/add` 仅执行 `wuzichukuService.insert(wuzichuku)`，不调用任何库存变更服务。
- **用户角色数据隔离**：当 session 中 `tableName == "yonghu"`（普通用户）时，`/page`、`/remind`、`/value`、`/group` 等端点会自动追加 `WHERE yonghuming = #{username}` 过滤条件。管理员不受限制。
- **出库记录来源有两条路径**：
  1. **手动创建**：管理员通过 `/save` 或 `/add` 直接创建（⚠️ 不扣减库存）
  2. **审批自动生成**：申领审批通过时由 `KucunServiceImpl.approveRequisition()` 自动创建，`chukuleixing = "申领出库"`，`chukubeizhu = "申领单号: XXX"`

#### 代码没有做什么（重大缺口）

- **⚠️ 手动出库不扣减库存**：这是当前系统最大的数据一致性缺口。管理员通过 `/save` 或 `/add` 直接创建出库记录时，`wuzixinxi.wuzishuliang` **不会自动减少**。只有通过申领审批流程产生的出库记录才会扣减库存。
- **`/save` 和 `/add` 无 `@Transactional`**：即使未来补充扣减逻辑，当前也缺乏事务保障。
- **`/update` 不同步库存差额**：修改出库数量不影响库存。
- **`/delete` 不回补库存**：删除出库记录不会将库存加回。
- **无库存充足性校验**：手动出库不检查库存是否足够，理论上可以出库超过实际库存。

### 3.4 WuzishenlingController — 物资申领

**路由前缀**：`/wuzishenling`
**注入服务**：`WuzishenlingService`、`KucunService`

#### 已实现的功能

| API 端点 | 功能说明 | 权限 | 用户过滤 |
|----------|----------|------|----------|
| `GET /page` | 后台分页查询申领记录（支持日期范围） | 需登录 | "yonghu"角色只能看自己的 |
| `GET /list` | 前台分页查询（支持日期范围） | @IgnoreAuth | 无过滤 |
| `GET /lists` | 全量列表 | 需登录 | 无 |
| `GET /query` | 单条查询 | 需登录 | 无 |
| `GET /info/{id}` | 按 ID 详情 | 需登录 | 无 |
| `GET /detail/{id}` | 按 ID 详情（前台） | @IgnoreAuth | 无 |
| `POST /save` | 创建申领单（自动设"待审核" + 快照库存） | 需登录 | — |
| `POST /add` | 创建申领单（同 /save） | 需登录 | — |
| `POST /update` | 修改申领记录 | 需登录 | — |
| `POST /delete` | 批量删除 | 需登录 | — |
| `POST /approve` | 审批通过（扣库存 + 自动生成出库记录） | 需登录 | — |
| `POST /reject` | 审批拒绝（不影响库存） | 需登录 | — |
| `GET /remind/{columnName}/{type}` | 提醒计数 | 需登录 | "yonghu"角色过滤 |

#### 代码实际做了什么

- **申领创建流程**（`/save`、`/add` → `kucunService.createRequisition()`）：
  1. 校验物资名称非空、申领数量 > 0
  2. 查询当前库存（`SELECT` 无锁，只读快照）
  3. 将当前库存值写入 `wuzishenling.wuzishuliang`（快照）
  4. 设置 `sfsh = "待审核"`
  5. 插入申领记录
  > **注意**：此步不检查申领数量是否超过库存，也不预扣库存。

- **审批通过流程**（`/approve` → `kucunService.approveRequisition(id, shhf)`）：
  1. 校验申领记录存在且状态为"待审核"
  2. `SELECT * FROM wuzixinxi WHERE wuzimingcheng = ? FOR UPDATE` — **悲观锁**
  3. 校验库存充足：`currentStock >= shenlingshuliang`，不足则抛出"库存不足"异常
  4. 扣减库存：`wuzixinxi.wuzishuliang -= shenlingshuliang`
  5. **自动生成出库记录**：创建 `WuzichukuEntity`，`chukuleixing = "申领出库"`，编号自动生成 `"CK" + timestamp`
  6. 更新申领状态：`sfsh = "已出库"`，写入审核回复 `shhf`

- **审批拒绝流程**（`/reject` → `kucunService.rejectRequisition(id, shhf)`）：
  1. 校验申领记录存在且状态为"待审核"
  2. 更新 `sfsh = "拒绝"`，写入 `shhf`
  3. 不修改库存

- **日期范围查询**：`/page` 和 `/list` 额外支持 `shenlingriqistart`、`shenlingriqiend` 参数（`@DateTimeFormat(pattern="yyyy-MM-dd")`）进行申领日期范围筛选。

#### 代码没有做什么

- **无统计 API**：本控制器没有 `/value`、`/group` 统计端点。若需要申领数据的统计报表，目前无法通过 API 获取。
- **`/update` 可篡改审核状态**：`updateById` 直接覆盖所有字段，普通用户理论上可以将 `sfsh` 从"待审核"改为"已出库"来绕过审批流程，且不会触发库存扣减。
- **`/delete` 不回滚已审批的库存**：删除已审批的申领记录不会将已扣减的库存加回。
- **申领创建时不校验库存是否充足**：用户可以提交申领数量超过库存的申请，只在审批环节才会报错。
- **无并发保护（创建阶段）**：`createRequisition` 中的库存快照查询没有使用 `FOR UPDATE`，多人同时申领可能看到相同的库存快照值（但这不影响实际扣减的正确性，因为审批阶段有悲观锁）。

## 四、库存联动机制总览（KucunService）

`KucunService` / `KucunServiceImpl` 是跨模块的库存编排层，被三个控制器注入使用：

```
                    ┌───────────────────────────────┐
                    │        KucunService            │
                    │  (库存编排服务 - 事务协调层)      │
                    ├───────────────────────────────┤
                    │ increaseStock()               │
                    │ createRequisition()           │
                    │ approveRequisition()          │
                    │ rejectRequisition()           │
                    │ lowStockAlert()               │
                    └──────┬──────┬──────┬──────────┘
                           │      │      │
              ┌────────────┘      │      └────────────┐
              ▼                   ▼                    ▼
    WuzirukuController  WuzishenlingController  WuzixinxiController
    (save/add 调用       (save/add/approve/     (lowStockAlert
     increaseStock)       reject 调用)           调用)
```

**注意**：`WuzichukuController` **没有注入 KucunService**，这是手动出库不联动库存的根本原因。

## 六、当前缺口明细清单

| 编号 | 缺口描述 | 影响范围 | 严重程度 | 涉及代码位置 |
|------|----------|----------|----------|-------------|
| GAP-1 | 手动出库（WuzichukuController `/save`、`/add`）不调用 KucunService，不扣减 `wuzixinxi.wuzishuliang` | 库存数据失真 | **高** | `WuzichukuController.java:131-148` |
| GAP-2 | 入库记录 `/update` 修改数量后不回算库存差额 | 库存数据失真 | **高** | `WuzirukuController.java` `/update` 端点 |

## 附录 A：WuzichukuController 现有统计 API 入参与口径

### A.1 聚合统计 — `/wuzichuku/value/{xColumnName}/{yColumnName}`

**HTTP 方法**：GET

**路径参数**：

| 参数 | 类型 | 说明 | 可选值举例 |
|------|------|------|-----------|
| `xColumnName` | String | 分组列名（GROUP BY 的维度） | `wuzifenlei`、`chukuleixing`、`yonghuming` |
| `yColumnName` | String | 聚合列名（SUM 的度量值） | `wuzishuliang` |

**查询参数**（通过 `@RequestParam Map` 传入，透传为 EntityWrapper 条件）：可传入实体任意字段作为等值过滤条件。

**用户角色过滤**：当 session `tableName == "yonghu"` 时，自动追加 `WHERE yonghuming = #{session.username}`。

**底层 SQL**（`WuzichukuDao.xml`）：
```sql
SELECT ${params.xColumn}, sum(${params.yColumn}) total
FROM wuzichuku
WHERE 1=1 ${ew.sqlSegment}
GROUP BY ${params.xColumn}
```

**返回格式**：`List<Map<String, Object>>`，每个 Map 包含分组列值和 `total` 字段。

**口径说明**：对 `wuzichuku` 表中满足过滤条件的记录，按 `xColumnName` 分组后，对 `yColumnName` 求 SUM。结果反映的是出库记录表中的流水合计，**不是**台账主表的实时库存。

---

### A.2 时间维度聚合统计 — `/wuzichuku/value/{xColumnName}/{yColumnName}/{timeStatType}`

**HTTP 方法**：GET

**路径参数**：

| 参数 | 类型 | 说明 | 可选值 |
|------|------|------|--------|
| `xColumnName` | String | 时间列名 | `chukuriqi`、`addtime` |
| `yColumnName` | String | 聚合列名 | `wuzishuliang` |
| `timeStatType` | String | 时间粒度 | `日`、`月`、`年` |

**用户角色过滤**：同 A.1。

**底层 SQL**（`WuzichukuDao.xml`）：
```sql
-- timeStatType == "日"
SELECT DATE_FORMAT(${params.xColumn},'%Y-%m-%d') ${params.xColumn},
       sum(${params.yColumn}) total
FROM wuzichuku WHERE 1=1 ${ew.sqlSegment}
GROUP BY DATE_FORMAT(${params.xColumn},'%Y-%m-%d')

-- timeStatType == "月"
SELECT DATE_FORMAT(${params.xColumn},'%Y-%m') ${params.xColumn},
       sum(${params.yColumn}) total
FROM wuzichuku WHERE 1=1 ${ew.sqlSegment}
GROUP BY DATE_FORMAT(${params.xColumn},'%Y-%m')

-- timeStatType == "年"
SELECT DATE_FORMAT(${params.xColumn},'%Y') ${params.xColumn},
       sum(${params.yColumn}) total
FROM wuzichuku WHERE 1=1 ${ew.sqlSegment}
GROUP BY DATE_FORMAT(${params.xColumn},'%Y')
```

**口径说明**：按日/月/年粒度对出库记录进行时间维度聚合。`DATE_FORMAT` 为 MySQL 函数，**SQL Server 环境需替换为 `FORMAT()` 或 `CONVERT()`**（当前代码未做兼容处理，SQL Server 下此接口会报错）。

---

### A.3 分组计数 — `/wuzichuku/group/{columnName}`

**HTTP 方法**：GET

**路径参数**：

| 参数 | 类型 | 说明 | 可选值举例 |
|------|------|------|-----------|
| `columnName` | String | 分组列名 | `wuzifenlei`、`chukuleixing`、`yonghuming` |

**用户角色过滤**：同 A.1。

**底层 SQL**（`WuzichukuDao.xml`）：
```sql
SELECT ${params.column}, count(1) total
FROM wuzichuku
WHERE 1=1 ${ew.sqlSegment}
GROUP BY ${params.column}
```

**口径说明**：按指定列分组后统计每组的记录条数。例如 `/wuzichuku/group/chukuleixing` 返回每种出库类型的出库笔数。

---

### A.4 SQL 注入风险提示

上述三个统计 API 的列名参数（`xColumnName`、`yColumnName`、`columnName`）直接通过 `${}` 拼接进 SQL（非 `#{}` 预编译），存在 **SQL 注入风险**。当前依赖前端控制传入值，后端未做列名白名单校验。
